--------------------------------------------------------------------------------
1. EXECUTIVE SUMMARY & CORE OBJECTIVE
--------------------------------------------------------------------------------
Standard Bukkit/Paper chunk force-loading methods (`Chunk#setForceLoaded(true)`) fail
to trigger random block ticks (such as sugarcane, bamboo, and crop growth) or natural
mob spawning cycles. Minecraft's internal world ticking engine explicitly requires an
active, registered `ServerPlayer` entity within simulation range (default ~128 blocks)
to allocate player-based chunk tickets and update spawn caps.

The "FakePlayerFarm" plugin solves this by refactoring standard entity injection into
a true Net.Minecraft.Server (NMS) `ServerPlayer` system. It injects spoofed player 
instances directly into the server's core network and player list infrastructure,
tricking the server into treating the NPC identically to a human player.

--------------------------------------------------------------------------------
2. KEY TECHNICAL ACHIEVEMENTS & REFACTORING JOURNEY
--------------------------------------------------------------------------------

[A] Modern NMS ServerPlayer Constructor & Injection Integration (Paper 26.2 / MC 1.21+)
    - Implemented `net.minecraft.server.level.ServerPlayer` instantiation using modern
      1.21+ Mojang Mappings.
    - Integrated `ClientInformation.createDefault()` to supply client parameters directly.
    - Post-`placeNewPlayer` Location Enforcement: Fixed Paper's playerdata loading reset
      by explicitly enforcing spawn coordinates via `handle.setPos()`, `handle.setRot()`,
      and `handle.setOldPosAndRot()` post-injection.

[B] Leak-Proof Spoofed Netty Network Pipeline (`Connection` & `EmbeddedChannel`)
    - Configured a zero-leak `EmbeddedChannel` with `Connection(PacketFlow.SERVERBOUND)`.
    - Added a dedicated Netty `ChannelOutboundHandlerAdapter` to release all outbound
      packet buffers (`ReferenceCountUtil.release(msg)`), eliminating memory accumulation
      in `EmbeddedChannel.outboundMessages`.
    - Resolved Netty `NullPointerException` by manually assigning public fields:
      `conn.channel = channel` and `conn.address = channel.remoteAddress()`.

[C] Multi-Dummy Per-Player Architecture (`max-dummies-per-player`)
    - Upgraded session registry from single-slot owner mapping to a unique `sessionId`
      architecture, enabling players to spawn up to `max-dummies-per-player` (e.g. 1, 2, 5+).
    - Unique Deterministic UUIDs: Generated distinct dummy UUIDs using
      `UUID.nameUUIDFromBytes(("afkdummy:" + ownerUUID + ":" + sessionId).getBytes())`
      to eliminate entity UUID collisions in Paper's `PlayerList` and `ChunkMap`.
    - Compliant `GameProfile` usernames with Adventure `Component` tab list display names.

[D] Hardened Protection & Event Safety
    - Interaction Safety: Filtered `PlayerInteractEntityEvent` to `EquipmentSlot.HAND` to
      prevent double GUI opening.
    - Comprehensive Piston Displacement Defense: Intercepts piston head extension block
      targets and sticky piston retraction destination blocks.
    - Explosion & Portal Immunity: Added `BlockExplodeEvent` (beds/respawn anchors) and
      `PlayerPortalEvent` / `EntityPortalEvent` cancellation.

[E] Atomic JSON Persistence & Concurrency
    - Storage rewritten to perform atomic file replacement (`dummies.json.tmp` -> `ATOMIC_MOVE`)
      under synchronization locks, eliminating file corruption during rapid async writes.
    - Dynamic `/afkdummy reload` that reschedules expiration cleanup tasks on the fly.

[F] bStats Metrics & Platform Analytics Integration
    - Integrated `org.bstats:bstats-bukkit:3.1.0` (relocated to `com.plugin.afkdummy.bstats`).
    - Custom Charts: Active dummy tracker (`active_dummies`), payment currency breakdown
      (`payment_item`), and max dummy limits per player (`max_dummies_per_player`).

3. PLUGIN FEATURES & SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
- **GUI Management Framework**: Exploit-proof inventory GUI allowing players to rent AFK
  dummies for discrete time tiers (1h, 3h, 12h, 24h) with multi-dummy limit progression.
- **Economic Item Deduction**: Atomic inventory storage item counting and removal using
  configured materials (default: DIAMONDS).
- **Protection & Anti-Griefing**: Complete event cancellation for dummy damage (all causes),
  mob targeting, piston pushes/pulls, vehicle entry, fishing hooks, portals, and explosions.
- **Persistence & Recovery**: Persistent JSON storage (`dummies.json`) with automated,
  delayed respawn upon server startup to ensure worlds are loaded prior to entity injection.
- **Skin Spoofing**: Asynchronous Mojang API skin fetching with shutdown safety guards.
- **Live Diagnostics & Metrics**: Periodically verifies chunk loading, mob counts, and
  `PlayerList` registration in `debug.log`, plus real-time bStats reporting.
